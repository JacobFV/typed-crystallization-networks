# Code generation: a typed program that emits runnable target-ISA source

*All figures recomputed from `out/bound.json` and `out/run.json`; both are
regenerated by `bound.py` and `run.py` on the repo `.venv`. Nothing in `tcn/`
or `generators/` was modified — `git status` shows only new files under
`research/code-generation/`.*

## 1. The target, and why this one

**Target language:** gate lists for `generators/logic` at width 3 — a sequence of
`(wire_a, wire_b, table)` triples, executed by that generator's own `evaluate`,
and expressible as the depth-independent `set[(index, wire_a, wire_b, table)]`
relation the generator already emits (`gate_set_value`). **Specification:** the
behaviour alone — the 8-entry truth table of the target function. **Artifact:** a
five-gate netlist that is run, not compared.

Chosen over the shell-command and own-algebra options for one reason: it is the
only one of the three where scoring is *execution*. A candidate is right iff the
gate list it emits reproduces the specified truth table on all eight assignments
under the generator's evaluator — exact, external to the search, no similarity
metric anywhere. It is also the exact inverse of section 15's interpreter: that
one read a gate list and evaluated it; this one is handed behaviour and writes
the gate list. And unlike the shell target it needs no live OS, so the whole
result is reproducible in seconds.

## 2. The bound, computed before searching (`bound.py`)

Wire values are carried as 8-bit masks over the eight assignments; the mask
algebra is checked against `generators.logic.generator.evaluate` on 2,000 random
netlists before any count is reported.

**The specification does not determine the program, and the numbers are large:**

| free gate lists, width 3 | programs | behaviours reached (of 256) | programs per behaviour: min / median / max |
|---|---|---|---|
| length 1 | 144 | 38 | 2 / 2 / 18 |
| length 2 | 36,864 | 152 | 8 / 8 / 5,304 |
| length 3 | 14,745,600 | 232 | 192 / 4,672 / 2,320,704 |

So a conforming program is emphatically not the intended one, and three gates do
not even reach 24 of the 256 behaviours.

**A target shape is therefore declared, and it is a bijection.** The Shannon
skeleton `[[0,1,t0],[0,1,t1],[3,2,4],[4,2,8],[5,6,14]]` — five gates, of which
three are fixed wiring and tables — covers **all 256 behaviours with exactly one
`(t0,t1)` pair each**. Restricting to it is the one structural prior in this
track, and it is the reason the search has a determined answer at all. It is not
an optimiser: it always emits five gates where fewer often suffice.

## 3. Stage A — learn the ISA's executor (`run.py`)

Supervision comes from the target instruction set, not from a hand-written
evaluator: targets are `evaluate(3, canonical(t0,t1), m)` for 12 sampled
`(t0,t1)` pairs × 8 assignments = 96 examples.

The scaffold declares a skeleton (a two-bit address, two tuple reads, one mux)
and **searches every convention**: which two inputs form the table address and in
which order (9), which cofactor each read serves (2×2), which input selects and
which arm it picks (12). Space **432**, `enumerate_prefix`, exhausted in
**0.021 s**.

* conforming **2**, certificate `complete`; the two are verified extensionally
  identical (the `v0`/`v1` swap with the mux arms swapped), so the executor is
  unique as a function.
* recovered: address `pack((x1, x0)) = 2·x0 + x1`, selector `x2`, and
  `out = x2 ? c1[j] : c0[j]`. The ISA's table bit order was discovered, not given.
* held out: **max error 0.0 over 1,952 examples** — all 244 unseen `(t0,t1)`
  pairs × 8 assignments.

Frozen and registered as a module (`module:2d6ab41f…`).

## 4. Stage B — the code generator, supervised on behaviour only

Scaffold: eight free address nodes `index(spec, k)` over the 8-entry
specification, forming two 4-bit gate tables, fed to the frozen executor.
Supervision is `spec[m]` — the behaviour. **No reference netlist is ever shown
to stage B.**

Which head is pinned by which selector value is read off stage A's selections,
not declared.

| split | train behaviours | head A space / conforming / certificate | head B | held-out behaviours emitted exactly |
|---|---|---|---|---|
| random 12 | 12 | 4,096 / **1** / `unique` | 4,096 / **1** / `unique` | **244 / 244 (1.000)** |
| popcount 2 (structural) | 28 | 4,096 / **1** / `unique` | 4,096 / **1** / `unique` | **228 / 228 (1.000)** |
| x2-independent (control) | 16 | 4,096 / **16** / `complete` | 4,096 / **16** / `complete` | 0 / 240 (0.000) |

Both solved splits recover the same emitter — addresses `(0,2,1,3)` and
`(4,6,5,7)`, the ISA's bit permutation — and it is exact on **256 of 256**
behaviours, the whole function space, at assignment accuracy 1.000.

The `popcount 2` split is the generalization-outside-training-structure test the
brief asks for: trained only on functions with exactly two satisfying
assignments, tested on every function of every other Hamming weight. Held-out
behaviours are unseen *targets*, not unseen seeds.

**Baselines, on the same held-out behaviours (random-12 split):**

| emitter | exact behaviour rate | per-assignment accuracy |
|---|---|---|
| **learned** | **1.000** | **1.000** |
| identity addresses `(0,1,2,3),(4,5,6,7)` | 0.246 | 0.748 |
| random addresses (mean of 64) | 0.015 | 0.571 |
| best constant netlist fitted on train | 0.004 | 0.495 |

The identity-address row is the load-bearing control: the naive reading of the
truth table is wrong on 3 of 4 behaviours, so the permutation the search
recovered is content, not bookkeeping.

**Emitted artifacts** (from `out/run.json`, each verified to round-trip through
`gate_set_value`/`gates_from_set` at capacity 5):

| specification | emitted gate list |
|---|---|
| `01101001` (three-way XOR) | `[[0,1,6],[0,1,9],[3,2,4],[4,2,8],[5,6,14]]` |
| `00010111` (majority) | `[[0,1,8],[0,1,14],[3,2,4],[4,2,8],[5,6,14]]` |
| `10000000` (NOR of all three) | `[[0,1,1],[0,1,0],[3,2,4],[4,2,8],[5,6,14]]` |

## 5. Staging, priced

Unstaged, the joint emitter space is `8^8 = 16,777,216`. `tcn.search.viability`
at its nominal 2e4 executions/s projects **80,531 s (22.4 h)**; at this track's
own measured rate (196,608 program-executions in 3.16 s = 62,200/s) it projects
**~25,900 s (7.2 h)**. Staged into two 4,096-program searches it is
**4.4 s** — a 2,048× space reduction and roughly a 5,900× time reduction, with
`unique` certificates on both halves instead of none. That is the same shape as
section 19 (50.7 days → 366 s) and section 12.

The staging is derived, not assumed: the split is possible only because stage A
found the selector, and the search is restricted to the examples where that
selector is 0 or 1.

## 6. The negative control, and what it certifies

The `x2_independent` split trains on the 16 behaviours that ignore `x2`. There
positions `m` and `m+4` of the specification always agree, so each head has
**16 conforming address tuples, certificate `complete`** — the specification set
provably does not determine the emitter — and the arbitrarily chosen conforming
program emits netlists that are exactly right on 0 of 240 held-out behaviours.
This is the failure the bound predicts, measured rather than argued, and it is
the reason the two working splits' `unique` certificates are the claim.

## 7. Certificate, in one sentence

Every search in this track exhausted its space: stage A, 432 programs, 2
conforming and extensionally identical; stage B, 4,096 programs per head,
**conforming = 1, certificate `unique`** on both heads under both non-degenerate
splits — so no initialization, ranking tie-break or seed could have chosen
differently, and AGENTS.md's stronger-than-ablation test is satisfied by
construction.

## 8. Limits, stated

* The target shape is declared. Without it the behaviour identifies a median of
  4,672 three-gate programs (section 2), so "the code generator emits *the*
  program" is only meaningful relative to a shape.
* Width 3 and one Shannon level. A recursive compiler for width `w` needs the
  emitter applied at `2^(w-2)` cofactors; the natural route is the `map`/frozen-
  module positional reuse of section 26, and it is not attempted here.
* The emitter is feed-forward and emits a fixed-length netlist. A
  variable-length gate list would need `enumerate_recurrent` and the
  `set[(index,…)]` view as an *output*, which no scorer in `tcn/search.py`
  currently supports.
* Gradient descent was not run on this task, so no surrogate-value report is
  owed; the `eq`/`lt` dead-surrogate family is bypassed entirely — the emitter
  path contains only `index`, `tuple`, `pack` and `mux`.
* Five gates always, minimal never: this is a compiler backend, not an optimiser.
